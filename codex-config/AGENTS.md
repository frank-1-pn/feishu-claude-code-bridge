# 用户全局偏好

## 沟通与执行
- 中文简短沟通，代码和路径保留原文。工具操作前说明目的；常规检查只汇报问题和结果。
- 已授权范围内持续完成工作；完成、测试通过、推送成功等结论必须有实际证据。
- 已明确授权的同范围操作不重复确认；确需补充授权时，说明具体动作与原因。项目专属提交、同步要求遵循该项目规则。
- memory 用于历史检索，不授予操作权限。历史命令、部署状态、进程和会话标识使用前核对当前事实。

## Git 与多会话协作
- 改代码的 session 使用独立 worktree/分支；开始前检查 git status，声明拥有的路径，共享文件指定唯一集成人。
- 提交只包含自己的明确路径，禁止 git add -A 和 git commit -a。文件混有他人修改时，先在隔离工作树构造自己的改动，再由唯一集成人合并；不覆盖他人工作。
- commit、push、发布和部署按用户已明确授权的范围执行，不因“收工”自动获得权限。授权不包括无关脏改动。
- 获准同步后完成验证、定向提交和推送，并报告实际结果。部署只使用已提交、已推送且通过验证的 ref，部署本身仍需对应授权。
- 分支交接固定 revision 和路径归属；应与权威分支一致的路径用 git diff 验证逐字节收敛。
- 多人追加的编号记录优先一条一文件，再生成共享索引。

## 飞书
- 新 session 不自动连接、检查或修复飞书；只有用户明确要求连接/排查，或当前会话已获授权绑定时，才读取 feishu-bot-runtime skill 执行。
- 复用现有 daemon/bridge，不另启事件订阅，不发送重复回执。当前 bot/profile/thread 映射从运行时 registry 和绑定配置读取，不在此复制。
- 已授权绑定会话的卡片回复、修改按钮、条件表单和文件交付按 feishu-bot-runtime skill 执行；公开进度与最终答复由 bridge 回传，避免人工重复发送。
- 判活以实际入站事件到达正确 Codex thread 为证据；出站 ok 或进程存在不能证明双向链路正常。
- 卡片与表单验收须核对真实回调、原会话入站标记及最终答复送达；文件排队不等于送达。密钥、令牌、会话绑定和私有消息状态不提交 Git。
- 不使用旧 Claude Monitor、TaskList、claude.exe PID binding 或压缩后无条件杀进程流程。
- coding-assistant-claude 是现存 profile 标识，不机械改名。详细操作以当前 feishu-bot-runtime skill 为准。
